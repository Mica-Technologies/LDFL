# Building from source

LDFL builds with Gradle using the GregTechCEu Buildscripts (RetroFuturaGradle). The mod targets
**Java 8**, but Gradle itself must run on a **JDK 17 to 22** (21 recommended; CI uses 21). Jabel
lets the source use newer syntax while still producing Java 8 bytecode.

## Requirements

- Git
- A JDK 21 (Azul Zulu, Temurin, or any other)

## Build

```bash
git clone https://github.com/Mica-Technologies/LDFL.git
cd LDFL
export JAVA_HOME=/path/to/jdk-21    # set this before every ./gradlew call
./gradlew build
```

The jar is written to `build/libs/`.

| Task | What it does |
| --- | --- |
| `./gradlew build` | Compile, run the unit tests, build the jar |
| `./gradlew test` | Unit tests only (pure JVM, a few seconds) |
| `./gradlew runClient` | Start a development client with the mod loaded |
| `./gradlew runServer` | Start a development dedicated server |

!!! warning "Don't build while the game is running"

    Never run a build while a `runClient` or `runServer` from the same checkout is still running.
    It rewrites the classpath the running game is loading from and corrupts it.

!!! warning "Don't update the buildscript"

    Do not run `gradle updateBuildScript`. The build script is pinned on purpose; see the note in
    `gradle.properties`.

## Regenerating assets

All of LDFL's art, sound and data files are generated by scripts in `tools/`, so they are
original and reproducible:

| Script | Generates |
| --- | --- |
| `pwsh -File tools/art/textures.ps1` | The hero item textures, drawn in code from simple shapes (`-Preview` writes an enlarged preview sheet) |
| `bash tools/audio/sounds.sh` | Every sound effect, synthesized from sine tones and noise with ffmpeg (needs ffmpeg with libvorbis) |
| `node tools/data/gen-advancements.js` | The advancement tree and the recipe-book unlocks |

## Previewing this wiki

The wiki is plain Markdown under `docs/`, built with MkDocs Material:

```bash
python -m pip install -r docs/requirements.txt
mkdocs serve        # live preview at http://127.0.0.1:8000
mkdocs build --strict
```

Pushing a change under `docs/` to `main` rebuilds and publishes the site automatically.

## Continuous integration

| Workflow | When | What |
| --- | --- | --- |
| Build Mod Release/Pre-Release | Every push to `main` | Builds and publishes a date-versioned **pre-release**; a manual run with `release=true` publishes a full release |
| Test Mod Build (PR) | Pull requests | Builds, runs the tests, and boots a real **dedicated server** to catch client-only code in common paths |
| Deploy Wiki | Pushes to `main` that touch `docs/` or `mkdocs.yml` | Builds this site with `--strict` and publishes it to GitHub Pages |
| Cleanup pre-releases | After each release build | Prunes old pre-releases |
